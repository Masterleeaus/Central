# Contributing to Titan Central

## Source layout

- Put HTTP routes, OIDC adapters and runtime wiring in `apps/control-api`.
- Put reusable identity, organisation, entitlement and product policy in `packages/control-plane/src`.
- Do not edit `packages/control-plane/dist` by hand; it is generated by the TypeScript build.
- Put reviewed Central database changes in `migrations`. Preserve applied migration bytes; add new numbered migrations. The separate `database/migrations` chain owns canonical company tables. Never apply either chain to Logto or product databases.
- Keep operational deployment evidence in `deploy`; never commit secrets or live customer data.

## Local workflow

Use Node.js 22 or later and Python 3 for the preflight suite.

```sh
npm ci
npm run build
npm start
npm test
npm run test:preflight
```

## Product identifiers

Public product names are Sorted, Supercharged and SkilledAt.Work. Legacy access/OIDC contracts still use `field`, `desk`, and `academy`; the canonical company registry uses `sorted`, `supercharged`, `lms` and `scheduled`. These namespaces are not interchangeable. Preserve distinct audiences and fail-closed validation; any ID transition needs an additive compatibility design and migration. Product-owned user/account IDs must be verified by the product that owns them.

## Security and deployment

Authorization must fail closed. Never derive product tenancy from email or user-provided account values. Do not mark deployment checks as passed without live evidence. Changes to OIDC scopes, audiences, session rules, migration semantics or cross-product access need focused review.
